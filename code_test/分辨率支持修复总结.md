# EoMT 分辨率支持修复总结

## 🎯 问题识别

您发现了一个关键问题：EoMT模型中有多处硬编码了224分辨率，这会导致在使用更大分辨率（如640x640）进行分割任务时出现问题。

## 🔍 发现的硬编码问题

### 1. ViT模型 (`models/vit.py`)
- ❌ 没有将`img_size`参数传递给DINOv3模型
- ❌ DINOv3模型始终使用默认的224x224分辨率

### 2. EoMT模型 (`models/eomt.py`)
- ❌ `_predict`方法中硬编码`img_size = 224`
- ❌ forward方法中使用固定的grid_size计算

## ✅ 修复方案

### 1. ViT模型修复
```python
# 修改前：使用torch.hub.load，无法传递img_size
model = torch.hub.load(repo_dir, 'dinov3_vitl16', source='local', weights=weights_path)

# 修改后：直接调用_make_dinov3_vit，支持自定义img_size
model = _make_dinov3_vit(
    img_size=max(img_size),  # 支持任意分辨率
    patch_size=patch_size,
    # ... 其他参数
)
```

### 2. EoMT模型修复
```python
# 修改前：硬编码224
img_size = 224  # 硬编码
grid_size = img_size // patch_size

# 修改后：动态计算
num_patch_tokens = x.shape[1]
grid_size = int(math.sqrt(num_patch_tokens))
# 支持从encoder获取实际图像尺寸
```

### 3. Attention Mask修复
```python
# 修改前：假设方形grid
grid_size = int(math.sqrt(H * W))
interpolated = F.interpolate(mask_logits, size=(grid_size, grid_size), mode="bilinear")

# 修改后：使用实际的H, W
interpolated = F.interpolate(mask_logits, size=(H, W), mode="bilinear")
```

### 1. 动态分辨率支持
- 支持任意16的倍数分辨率
- 自动计算patch grid尺寸

## 🔧 技术细节

### Patch Size计算
- 输入分辨率：H × W
- Patch size：16 × 16
- Grid size：(H/16) × (W/16)
- Upscale输出：(H/16*4) × (W/16*4) = (H/4) × (W/4)

### 支持的分辨率要求
- 必须是16的倍数（patch_size=16）
- 推荐使用常见的分辨率：224, 448, 512, 640等
- 理论上支持任意16倍数分辨率
